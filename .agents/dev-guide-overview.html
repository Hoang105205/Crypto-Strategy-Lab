Why Spec-Driven Development?

Stop coding before thinking. Start with the spec.

⚠️

Traditional

  • Code first, document later (or never)
  • Architecture lives in someone's head
  • Decisions are forgotten or lost
  • No traceability from requirement to code
  • Onboarding = reading source code
✅

SDD Kit

  • Spec before code — every feature
  • KB is the single source of truth
  • ADRs record why decisions were made
  • Full traceability: spec → plan → tasks → code
  • Onboarding = read the KB

Knowledge Base Structure

Single source of truth — progressive disclosure, never loaded all at once

kb/ ├── INDEX.md # KB sitemap ├── CONSTITUTION.md # Non-negotiable principles ├── ARCHITECTURE.md # System architecture ├── DESIGN.md # FE/UX design system ├── MODULES.md # Module boundaries (index) ├── GLOSSARY.md # Domain terms ├── CONTRIBUTING.md # Team conventions ├── ADR/ # Why + How (decisions) ├── contracts/ # API/data contracts (SSoT) ├── modules/ # Per-module architecture (WHAT) ├── flows/ # E2E business use cases (cross-module) └── patterns/ # Design pattern catalog

Three Perspectives, One KB

Module files, flow files, and ADRs work together

📦
Module Files
What's inside?
kb/modules/{name}.md
Components, design patterns, internal data flows, sequence diagrams
🔄
Flow Files
How do modules cooperate?
kb/flows/{name}.md
E2E steps, preconditions, business rules, alternative & error paths
💡
ADR Files
Why was it decided?
kb/ADR/000X-*.md
Decision context, rationale, alternatives, consequences

Quick Start

From zero to first feature in 5 steps

01

Initialize the KB

Run /hoang-kb-init "e-commerce with catalog, cart, checkout" — creates all KB files including modules/ and flows/

02

Customize & Assign Owners

Fill CONSTITUTION.md, adjust ARCHITECTURE.md, assign module owners to kb/modules/{name}.md and flow owners to kb/flows/{name}.md

03

Start Your First Feature

Run /hoang-sdd-on "allow user to login" — the orchestrator proposes the full 7-phase workflow

04

Execute the Pipeline

/hoang-sdd-specify → /hoang-sdd-plan → /hoang-sdd-tasks → /hoang-sdd-implement

05

Verify & Converge

Run /hoang-sdd-analyze for consistency, then /hoang-sdd-converge to close any gaps
