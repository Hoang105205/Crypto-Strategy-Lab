##### [MEDIUM] [F-101]: Composite endpoint uses `childStrategyNames` not `childStrategyIds`
**File**: `apps/backend/src/strategy/controllers/strategy.controller.ts:57`
**Check**: 4b (Contract Compliance)
**Issue**: Contract `strategy.yaml` line 165 defines `POST /api/strategies/composite` with `childStrategyIds: UUID[]`. But the controller's `CreateCompositeDto` uses `childStrategyNames` (string[] — strategy names, not UUIDs). The controller resolves children by name from StrategyRegistry, not by version ID.
**Impact**: Minor contract drift — the implementation works but doesn't match the documented contract shape. Frontend must send names not IDs.
**Action**: Either update `strategy.yaml` to reflect the actual `childStrategyNames` implementation, or update the DTO to accept `childStrategyIds` per contract. Recommend updating the contract since name-based lookup is more user-friendly for the frontend.

**Issue**: Contract says `POST /api/strategies/backtest` accepts `strategyVersionId: UUID`. Controller uses `dto.strategyName` to look up from registry, then creates a version. This is semantically correct (creates a new version before backtesting) but differs from the documented contract.
**Impact**: Frontend sends `strategyName` not `strategyVersionId`. The response correctly includes `strategyVersionId`. Minor contract documentation drift.

**File**: `apps/backend/src/news/news.module.ts:17-18`
**Check**: 4d (Module Boundary Compliance)
**Issue**: News module imports `StrategyRegistry` and `StrategyRuntimeModule` directly from `../strategy/`. Per the plan (§4.5), modules should communicate only through shared interfaces. The `NewsSentimentStrategy` needs to register itself, but the import creates a compile-time dependency from `news/` to `strategy/`.
**Impact**: If the strategy module's internal structure changes, the news module import path breaks. This is an architectural coupling that weakens the independence claim.
**Action**: Acceptable for now — the registration pattern requires access to the registry. Consider exposing a `StrategyRegistrationPort` interface in `shared/` that the strategy module provides. **Not blocking for demo**, but should be discussed for architecture cleanup.

##### [MEDIUM] [F-106]: `getLatestSentimentScoreSync()` returns hardcoded 0.0
**File**: `apps/backend/src/news/strategies/sentiment.strategy.ts:139-141`
**Check**: 4b (Contract Compliance)
**Issue**: The synchronous `analyze()` method calls `getLatestSentimentScoreSync()` which returns hardcoded `0.0`. This means the synchronous path always returns `HOLD`. Only the `analyzeAsync()` path queries real sentiment data.
**Impact**: If the Backtester uses `strategy.analyze()` (sync), `NewsSentimentStrategy` always returns HOLD — making it useless in backtest composites. The backtester code (`backtester.service.ts:31-33`) checks for `analyzeAsync` and prefers it, so this is partially mitigated.
**Action**: Verify that the backtester always uses `analyzeAsync()` for NewsSentimentStrategy. If not, implement a proper sync fallback using cached sentiment data.
