##### [MEDIUM] [F-003]: ARCHITECTURE.md type naming inconsistency (ICandle vs Candle)
**File**: `kb/ARCHITECTURE.md` lines 52 vs 82
**Check**: 3e (Cross-Reference Integrity) / 3f (Plan Alignment)
**Issue**: Line 52 (in `apps/backend/src/shared/types/`) lists `ICandle, ITrade, ISignal` with the `I` prefix. Line 82 (in `libs/shared/src/types/`) lists `Candle, Signal, BacktestResult` without the `I` prefix. The contract (`kb/contracts/market-data.yaml`) and `kb/GLOSSARY.md` use `Candle` (no `I` prefix). GLOSSARY naming conventions state: "Interfaces: `I` prefix (e.g., `IMarketDataAdapter`)". Data types like `Candle` and `Signal` are not interfaces — they should not have the `I` prefix.
**Impact**: If code follows line 52's naming, shared types will be `ICandle`/`ISignal` — inconsistent with the contract and GLOSSARY. This creates confusion about what is an interface vs a data type, and violates the naming convention before coding even starts.
**Action**: Standardize on `Candle`, `Signal`, `Trade` (no `I` prefix) across ARCHITECTURE.md, ADRs, and all KB files. Update line 52 to match line 82. The `I` prefix is reserved for interfaces (`IMarketDataAdapter`, `IStrategy`, `IEventBus`).
