01 / 20 Software Architecture · Project Plan

Crypto Strategy Lab

Analyze, combine, and evaluate crypto trading strategies — with real-time Binance data, backtesting, ranking, and a continuous search loop.

4 fullstack members · 4 weeks · Modular Monolith

02 / 20 Core Thesis

Architecture quality over trading profit

  • The grading target is modifiability, scalability, extensibility — not P&L
  • New strategy → 1 file + 1 register() call
  • New search algorithm → 1 class implementing IStrategyGenerator
  • New data provider → 1 class implementing IMarketDataAdapter
  • Every extension point must be demonstrable in the demo
03 / 20 Architecture Decisions

The stack is decided up front

DecisionChoiceRationale
ArchitectureModular Monolith4 people / 4 weeks. Clean boundaries now, extract later.
BackendNestJS (TS)Each NestJS module maps to a domain module. Built-in DI + events.
FrontendNext.js (TS)App router dashboard, real-time via WebSocket.
Module commEventEmitter2Event-driven. Swap to Redis Pub/Sub later if needed.
ExtensibilityRegistry + AdapterPlugin arch for strategies, adapters for data sources.
DatabasePostgreSQL + PrismaType-safe ORM. JSONB for flexible strategy params.
SentimentPython FastAPIML ecosystem, isolated process. Frontend never touches it.

12 / 20 Module Deep-Dive

Member B — Strategy Engine

BACKEND · DOMAIN LOGIC
  • StrategyRegistry — register() + analyze() pipeline
  • 4 strategies: MA · RSI · Bollinger · Support/Resistance
  • Composite: MajorityVote + WeightedScore combiners
  • Backtester + Evaluator (Return, WinRate, MDD, Sharpe)
  • Search Engine: Random + Domain-Guided generators
FRONTEND · STRATEGY BUILDER
  • Strategy selection + parameter editor
  • Composite builder — drag & combine strategies
  • Trade detail table with P&L

Interview: Plugin Architecture = Open-Closed Principle. New strategy → zero changes elsewhere.

13 / 20 Module Deep-Dive

Member C — News & Sentiment

NESTJS + PYTHON SERVICE
  • INewsProvider — RSS adapter + CryptoPanic adapter
  • Cron collection → normalize → dedupe → store
  • SentimentClient → isolated Python FastAPI (VADER)
  • SentimentStrategy — plugs into Registry, returns HOLD when service is down
FRONTEND · NEWS FEED
  • News feed with sentiment badges
  • Sentiment timeline chart + aggregate gauge

Interview: Process Isolation — Python crashes ≠ NestJS crashes. Graceful degradation via HOLD fallback.

14 / 20 Module Deep-Dive

Member D — the system's nervous system

BACKEND · INFRASTRUCTURE
  • events/ — EventEmitter2, typed events, flow docs
  • queue/ — worker pool, retry, dead-letter queue
  • leaderboard/ — Observer of BacktestCompleted, Top-K
  • loop/ — orchestrates search via events, not calls
  • dashboard/ — API composition layer (BFF)
FRONTEND · DASHBOARD + DESIGN
  • Leaderboard table — sortable by any metric
  • Loop status panel — progress, start/stop/pause
  • App shell, WebSocket provider, common UI
  • Design system — DESIGN.md owner

Interview: Event-Driven + Job Queue/Worker + Observer — three patterns, one owner.
