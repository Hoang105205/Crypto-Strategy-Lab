# Feature Specification: Base Technical Strategies

**Feature**: `base-strategies`
**Created**: 2026-08-11
**Status**: Draft
**Input**: User description: "Triển khai 4 chiến lược kỹ thuật cơ sở: Moving Average (MA), Relative Strength Index (RSI), Bollinger Bands, và Support/Resistance. Chú ý trả về đúng chuẩn Signal và cắm vào StrategyRegistry"

## User Scenarios & Testing

### User Story 1 - Moving Average (MA) Strategy (Priority: P1)

As a trader or backtest configuration, I want to use a Moving Average strategy so that I can generate trading signals based on simple moving average crosses or price-to-MA relationships.

**Why this priority**: MA is the most foundational trend-following indicator.
**Independent Test**: Provide a series of `Candle` objects where the latest closing price crosses above a calculated moving average. Verify the strategy returns a `Signal` with `action: SignalAction.BUY`.

**Acceptance Scenarios**:
1. **Given** an MA strategy configured with period N, **When** price crosses above MA(N), **Then** return BUY signal.
2. **Given** an MA strategy configured with period N, **When** price crosses below MA(N), **Then** return SELL signal.
3. **Given** price remains on one side of MA without crossing, **When** analyzed, **Then** return HOLD signal.

---

### User Story 2 - Relative Strength Index (RSI) Strategy (Priority: P1)

As a trader, I want to use an RSI strategy so that I can generate signals based on overbought (e.g., >70) and oversold (e.g., <30) momentum conditions.

**Why this priority**: RSI is a core momentum indicator required for basic mean-reversion trading.
**Independent Test**: Provide a candle series where the calculated RSI drops below 30 and then ticks up. Verify the strategy returns a BUY signal.

**Acceptance Scenarios**:
1. **Given** an RSI strategy configured with period N (usually 14), **When** RSI drops below oversold threshold (e.g. 30), **Then** return BUY signal.
2. **Given** an RSI strategy, **When** RSI rises above overbought threshold (e.g. 70), **Then** return SELL signal.

---

### User Story 3 - Bollinger Bands Strategy (Priority: P2)

As a trader, I want to use Bollinger Bands so that I can generate signals when the price breaks outside the standard deviation bands, indicating potential mean reversion or breakout.

**Why this priority**: Highly effective volatility-based indicator, often combined with RSI.
**Independent Test**: Provide a candle series where the price closes below the lower Bollinger Band. Verify a BUY signal is generated (assuming mean reversion logic).

**Acceptance Scenarios**:
1. **Given** a Bollinger Bands strategy (period N, stdDev D), **When** price touches or crosses below the lower band, **Then** return BUY signal.
2. **Given** a Bollinger Bands strategy, **When** price touches or crosses above the upper band, **Then** return SELL signal.

---

### User Story 4 - Support and Resistance (SR) Strategy (Priority: P2)

As a trader, I want to use a Support/Resistance strategy so that I can trade bounces or breakouts from historical price levels.

**Why this priority**: Price action trading relies heavily on horizontal levels.
**Independent Test**: Provide candles forming a clear support level. When the price touches the support level and rejects, verify a BUY signal.

**Acceptance Scenarios**:
1. **Given** an SR strategy, **When** price approaches a detected support level and bounces, **Then** return BUY signal.
2. **Given** an SR strategy, **When** price breaks decisively below a support level, **Then** return SELL (breakout) signal.

## Requirements

### Functional Requirements
- **FR-001**: System MUST implement `MovingAverageStrategy` adhering to the `IStrategy` interface.
- **FR-002**: System MUST implement `RsiStrategy` adhering to the `IStrategy` interface.
- **FR-003**: System MUST implement `BollingerBandsStrategy` adhering to the `IStrategy` interface.
- **FR-004**: System MUST implement `SupportResistanceStrategy` adhering to the `IStrategy` interface.
- **FR-005**: All strategies MUST implement the `analyze(candles: Candle[]): Signal` method, returning a valid `Signal` object with `action` (`BUY`, `SELL`, `HOLD`), `confidence`, and `metadata`.
- **FR-006**: All strategies MUST provide a `getParameters()` method returning their respective configuration (e.g., period, thresholds).
- **FR-007**: All strategies MUST be registered into the central `StrategyRegistry` upon application startup (via `StrategyModule` or a dedicated provider).

### Key Entities
- **IStrategy**: The contract all 4 strategies must implement (`getType()`, `getName()`, `analyze()`, `getParameters()`).
- **Candle**: The input time-series data containing open, high, low, close prices.
- **Signal**: The output decision (BUY, SELL, HOLD) generated by the mathematical evaluation of the candles.
- **StrategyRegistry**: The registry where these 4 strategies will be injected/registered.

## Success Criteria
- **SC-001**: All 4 strategies compile and pass unit tests verifying their mathematical logic against mock candle data.
- **SC-002**: All 4 strategies are successfully retrievable from `StrategyRegistry` via `registry.get(nameOrType)`.
- **SC-003**: Passing a valid array of `Candle` objects to any strategy's `analyze()` method successfully yields a `Signal` without throwing runtime errors.

## Assumptions
- We will use a reliable mathematical library (e.g., `technicalindicators` or custom robust math utilities) to calculate RSI, MA, and Bollinger Bands to avoid reinventing the wheel and ensure accuracy.
- Strategies process arrays of `Candle` objects synchronously in-memory.
