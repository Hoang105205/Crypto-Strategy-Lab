# Feature Specification: Gemini LLM Web Crawler Selector Discovery & Self-Healing

**Feature**: `gemini-crawler-selector-discovery`  
**Created**: 2026-08-31  
**Status**: Draft  
**Input**: "Tích hợp Google Gemini LLM API vào CrawlerDiscoveryService: 1. Tạo GeminiDiscoveryClient sử dụng GEMINI_API_KEY để gửi trích đoạn DOM HTML và nhận về JSON CSS Selectors. 2. Xây dựng prompt chuyên dụng cho LLM với Structured Outputs. 3. Graceful Degradation: fallback về Cheerio DOM Heuristics khi API Key trống/lỗi. 4. Bổ sung Unit Tests."

---

## User Scenarios & Testing

### User Story 1 - AI-Powered Automated CSS Selector Discovery (Priority: P1)
As a Crypto Strategy Lab system administrator or crawler orchestrator,  
I want the system to utilize Google Gemini 2.5 Flash LLM to semantically understand HTML snippets of new or redesigned crypto news portals,  
So that accurate CSS selectors (`container`, `title`, `content`, `link`, `date`) are automatically discovered and persisted in PostgreSQL without manual scraping code.

**Why this priority**: Core deliverable for ADR-0014 and requirement §28 (decoupling from static crawler scripts).  
**Independent Test**: Provide an HTML snippet with `GEMINI_API_KEY` configured, invoke `discoverSelectors()`, and assert that the returned `DiscoveredRule` contains valid, semantic CSS selector strings generated by Gemini.

**Acceptance Scenarios**:
1. **Given** a valid HTML snippet of a news portal and a configured `GEMINI_API_KEY`, **When** `CrawlerDiscoveryService.discoverSelectors()` is invoked, **Then** `GeminiDiscoveryClient` sends a prompt to Gemini 2.5 Flash and returns a structured `DiscoveredRule` JSON matching the DOM.
2. **Given** valid selectors are returned from Gemini, **When** saved into PostgreSQL, **Then** `CrawlerRule` is upserted with `isActive = true` and updated `lastDiscoveredAt`.

---

### User Story 2 - Self-Healing Pipeline Integration (Priority: P1)
As a continuous news ingestion worker (`WebCrawlerProvider`),  
I want the crawler to automatically trigger the Gemini discovery client when a target website updates its layout and cached selectors yield 0 articles,  
So that scraping rules are repaired on-the-fly without developer intervention.

**Why this priority**: Fulfills Tier 3 of ADR-0014 (Self-Healing Loop) ensuring uninterrupted news flow.  
**Independent Test**: Pass a mock layout change resulting in 0 parsed items; verify that `CrawlerDiscoveryService.repairSelectors()` invokes Gemini, updates the database, and re-parses articles successfully.

**Acceptance Scenarios**:
1. **Given** an existing `CrawlerRule` that extracts 0 articles from valid HTML (>500 chars), **When** `WebCrawlerProvider` detects extraction failure, **Then** it triggers `repairSelectors()`, which calls Gemini to discover new selectors and updates PostgreSQL.

---

### User Story 3 - Fault-Tolerant Graceful Fallback to Cheerio Heuristics (Priority: P2)
As a reliable trading platform,  
I want the system to seamlessly fallback to semantic Cheerio DOM heuristics if `GEMINI_API_KEY` is missing, invalid, or experiencing rate limits (HTTP 429) or network timeouts,  
So that news ingestion and backend processes never crash or block trading strategies.

**Why this priority**: Guarantees system resilience per Constitution Art IV and ADR-0010/0014.  
**Independent Test**: Mock a Gemini API 503 error, 429 rate limit, or empty `GEMINI_API_KEY`; verify that `discoverSelectors()` logs a warning and returns candidate selectors from Cheerio heuristics cleanly.

**Acceptance Scenarios**:
1. **Given** `GEMINI_API_KEY` is undefined or Gemini API throws an error, **When** discovery is triggered, **Then** `GeminiDiscoveryClient` logs a warning and gracefully delegates to Cheerio heuristics, returning a valid `DiscoveredRule`.

---

## Edge Cases
- **Empty or corrupt HTML**: If HTML sample is empty or whitespace, throw a descriptive error immediately before calling Gemini to conserve API quota.
- **Large HTML Payloads**: Truncate/sanitize HTML sample to relevant `<main>`, `<article>`, or `<body>` sections (max ~30KB) to minimize token consumption and avoid LLM context bloat.
- **Malformed JSON response from LLM**: Handle JSON parsing exceptions with regex extraction or immediate Cheerio fallback.
- **Rate Limit / Quota Exceeded (HTTP 429)**: Catch HTTP 429 status from Gemini API and immediately fallback to Cheerio heuristics with zero latency penalty.

## Requirements

### Functional Requirements
- **FR-001**: System MUST provide a dedicated `GeminiDiscoveryClient` in `apps/backend/src/news/services/gemini-discovery.client.ts` communicating with Google Gemini API (`gemini-2.5-flash`).
- **FR-002**: `GeminiDiscoveryClient` MUST read `GEMINI_API_KEY` and optional `GEMINI_MODEL` (default: `gemini-2.5-flash`) from environment variables.
- **FR-003**: System MUST provide structured prompt instructions to Gemini requesting strict JSON output containing: `containerSelector`, `titleSelector`, `contentSelector`, `linkSelector`, and `dateSelector`.
- **FR-004**: System MUST enforce a 10-second timeout on Gemini API requests using `AbortController` to satisfy SLA constraints.
- **FR-005**: If Gemini API call fails (network timeout, rate limit 429, missing API key, or invalid response), `CrawlerDiscoveryService` MUST gracefully fallback to `CheerioHeuristicDiscovery` without throwing unhandled exceptions.
- **FR-006**: Discovered selectors from Gemini or fallback MUST be upserted into PostgreSQL `CrawlerRule` table.
- **FR-007**: Unit tests MUST cover successful Gemini discovery, Gemini API error handling/fallback, and missing API key scenarios.

### Key Entities
- **`DiscoveredRule`**: In-memory DTO containing `domain`, `targetUrl`, `containerSelector`, `titleSelector`, `contentSelector`, `linkSelector`, `dateSelector`.
- **`CrawlerRule`**: Prisma entity in PostgreSQL storing cached selectors per domain with `isActive`, `lastDiscoveredAt`.

---

## Success Criteria
- **SC-001**: 100% of selector discovery requests succeed (either via Gemini LLM or Cheerio fallback).
- **SC-002**: Zero server crashes or blocked crawler jobs when `GEMINI_API_KEY` is unset or invalid.
- **SC-003**: 100% unit test pass rate across Gemini discovery and fallback suites.

---

## Assumptions
- Default LLM model is `gemini-2.5-flash` due to its high speed, low latency, and strong HTML parsing capabilities.
- Direct REST HTTP endpoint (`https://generativelanguage.googleapis.com/v1beta/models/...`) or official SDK is used for lightweight dependency footprint.
